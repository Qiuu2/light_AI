## 1. 规范说明

### 1.1 名词定义
- 作息（方案）：`schedule` 
作息方案 包括多个任务
- 任务：`task`
任务包括对于一个媒体的规定，例如在那些`terminal`（终端）/`zone`（分区）什么时间播放、播放多长时间。
- 媒体：`media`
媒体是一个可以播放的音频
- 分区：`zone`
一个`zone`（分区）包括一个或多个`terminal`（终端）
- 终端：`terminal`
`terminal`（终端）属于`zone`（分区），也可以不属于任何`zone`

### 1.2 命名建议
- 意图（`intent`，即系统内部英文意图标识）命名使用“动词+名词”结构，尽量表达动作本身，例如：作息移动`move_schedule`、任务媒体替换`replace_media_in_task`。

### 1.3 槽位说明（`slots`，槽位集合）
- `[必填]`：常规业务中通常需要提供的信息。
- `[必填*]`：同组槽位中至少出现一个即可。
- `[选填]`：可缺省，系统可走默认逻辑或后续补问。

### 1.4 系统默认配置（非 NLU 槽位）
- `default_schedule_kind` 是系统侧默认配置，不属于用户输入槽位，也不参与语料标注、BIO 标签或 NLU 槽位抽取。
- `create_schedule` 执行时可以使用 `default_schedule_kind` 选择内部模板，但它不能替代用户提供的 `schedule_name`。

### 2.1 强范式部分说明

#### `source_time` / `end_time` 时间格式举例

下述 `{time}` / `{date}` / `{weekday}` 等均为占位符。

- **纯时刻**：`{HH}:{MM}`、`{H}:{MM}`、`{HH}:{MM}:{SS}`、`{H}点`、`{H}点{MM}分`、`{上午/下午}{H}点`、`{上午/下午}{H}点半`
- **时间范围**：`{time}-{time}`、`{time}~{time}`、`{H}点到{H}点`、`{上午/下午}{time}到{上午/下午}{time}`（通常拆为 `source_time` + `end_time`）
- **星期/周几/礼拜几**：`周{一..日/天}`、`星期{一..日/天}`、`礼拜{一..日/天}`
- **星期 + 时刻**：`{weekday}{上午/下午}{time}`、`{weekday}{time}`、`{weekday}{H}点半`
- **日期**：`{M}月{D}日`、`{M}月{D}号`、`{YYYY}年{M}月{D}日`、`{YYYY}-{MM}-{DD}`、`{YYYY}/{MM}/{DD}`
- **日期 + 时刻**：`{date}{上午/下午}{time}`、`{YYYY}-{MM}-{DD} {time}`、`{YYYY}-{MM}-{DD}T{time}`
- **相对日期**：`今天/昨天/明天/后天/大后天`、`这周/本周/上周/下周/下下周`、`这个月/上个月/下个月`、`今年/明年`
- **相对日期 + 时刻**：`{相对日期}{上午/下午}{time}`、`下周{weekday}{time}`
- **模糊时间段**：`早上/上午/中午/下午/晚上/凌晨`
- **多时间点表达**：当业务需要两个时间锚点时，优先分别标注到 `source_time` 与 `end_time`，不再将多个时间值逗号拼接进同一个槽位。

#### `time_offset`（时间位移量/播放时长）格式举例

{N}：正整数（阿拉伯数字或中文数字，如 3、三、两）
{unit}：秒/分钟/分/小时/时/天/周/礼拜/月/个月/年
支持：半、一个半、{N}个{unit}、{N}{unit}{N}{unit}

## 3.1 重要意图（核心功能）

### 3.1.1 作息方案管理

#### 3.1.1.1 单向挪动作息方案（`move_schedule`）
- 功能：把某作息方案下某一时间点的任务迁移到另一个时间点。
- 槽位约束：
- `[必填]` `source_time`（源时间）、`end_time`（目标时间/结束时间）
- `[必填*]` 无
- `[选填]` `schedule_name`（作息方案名称）, `task_name`（任务名称） 
- 选填默认值：`schedule_name`（作息方案名称） 默认当前正在生效/激活的作息方案。
- 典型指令：将“春季作息”中周一的任务挪到周六。
- 典型指令：将“春季作息”中周一的眼操任务挪到周六。

#### 3.1.1.2 双向对调作息方案（`swap_schedule`）
- 功能：交换同一作息方案内两个时间点的任务。
- 槽位约束：
- `[必填]` `source_time`（源时间）
- `[必填*]` 无
- `[选填]` `schedule_name`（作息方案名称）, `task_name`（任务名称）
- 选填默认值：`schedule_name`（作息方案名称） 默认当前正在生效/激活的作息方案。
- 说明：`source_time` 表示第一个时间锚点，`end_time` 表示第二个时间锚点；训练与标注统一采用双槽位写法。
- 典型指令：把“春季作息”中周一和周五的任务对调。

#### 3.1.1.3 取消作息中的任务（`cancel_schedule`）
- 功能：按时间段或任务名称取消作息任务。
- 槽位约束：
- `[必填]` 无
- `[必填*]` 无
- `[选填]` `schedule_name`（作息方案名称）、`source_time`（源时间）、`end_time`（目标时间/结束时间）、`task_name`（任务名称）
- 选填默认值：
- `schedule_name`（作息方案名称） 默认当前唯一启用中的作息方案；若不存在唯一启用方案，则追问补充方案名称。
- `task_name`（任务名称） 未给时默认作用于命中时间范围内全部任务。
- `source_time/end_time`（源时间/目标时间）可以无默认值。
- 说明：
- 日期范围批量取消优先使用 `source_time + end_time` 双槽位表达。
- “取消执行/先取消执行/停掉” 仅视为取消措辞，不自动等同一次性；只有出现“一次性/本次/临时/只这一次”等明确词时才进入 once 语义。


#### 3.1.1.4 新建作息方案（`create_schedule`）
- 功能：创建新的作息方案。
- 说明：`schedule_name` 是用户必填槽位；`default_schedule_kind` 若已配置，仅作为内部模板选择依据，不属于 NLU 槽位。
- 槽位约束：
- `[必填]` `schedule_name`（作息方案名称）
- `[必填*]` 无
- `[选填]` `time_offset`（时间位移量/播放时长）、`source_time`（源时间）、`end_time`（目标时间/结束时间）
- 选填默认值：
- `time_offset`（时间位移量/播放时长） 默认长期有效。
- `source_time`（源时间） 默认当天 `00:00`。
- `end_time`（目标时间/结束时间） 默认不设结束时间。
- 典型指令：新建作息方案，名称为小学上学期作息方案。

### 3.1.2 媒体管理

#### 3.1.2.1 即时媒体播放（`play_media`）
- 功能：对终端/分区即时播放指定媒体。
- 槽位约束：
- `[必填]` `media_name`（媒体名称）
- `[必填*]` `zone_name`（分区名称）、`terminal_id`（终端编号）、`terminal_name`（终端名称）
- `[选填]` `time_offset`（时间位移量/播放时长）、`play_count`（播放次数）、`volume`（音量表达）
- 选填默认值：
- `time_offset/play_count`（时间位移量或播放次数）均缺失时默认 `play_count=1次`（播放次数为1次）。
- `volume`（音量表达） 默认沿用当前任务/系统音量。 方向+音量
- 典型指令：给操场、食堂、教学楼播放国歌。

## 附录C. 测试数据生成规则（）

### C.1 训练数据总体原则
- 生成与训练时，不需要严格受“必填/选填”约束。
- 即使某些常规“必填”槽位在文本中未出现，也允许作为有效训练样本。
- 缺失信息将在后续交互（追问/选择）补齐，不属于本阶段数据生成范围。

### C.2 覆盖率目标
- 对于有 `n` 个“必填”、`m` 个“选填”的意图，尽量覆盖组合空间：`2^(n+m)`。
- 目前较弱（多相同槽位识别）
- 数据分布建议：
  - 70%：包含全部常规必填槽位；选填槽位做均匀覆盖。
  - 30%：必填与选填均随机缺省，覆盖各种缺失组合，尽量均匀。

### C.3 强约束（必须满足）
1. `slots`（槽位字典）中的 `value`（槽位值）必须是 `string`（字符串）。
2. 同一槽位多个值时，用英文逗号拼接为一个字符串，例如：`"周一,周三"`。
3. `slots` 中出现的值，必须与 `text`（用户原文文本）中片段逐字匹配，不做归一化替换。
4. 若某槽位未在 `text`（用户原文文本）中出现，可不填该槽位。
5. `text`（用户原文文本）必须为中文，空格会被删除。

### C.4 数据格式（JSON 示例）

```json
{
  "data": [
    {
      "text": "{sentence}",
      "intent": "{intent_name}",
      "slots": {
        "{slot_1}": "{value_1}",
        "{slot_2}": "{value_2}",
        "{slot_3}": "{value_3},{value_4}"
      }
    }
  ]
}
```

- 字段说明（给不熟悉英文字段名的读者）：
  - `data`：样本列表（数据数组）。
  - `text`：用户原文文本。
  - `intent`：意图英文标识（对应上文意图清单）。
  - `slots`：槽位字典（键是槽位英文名，值是槽位原文字符串）。
  - `{slot_1}` / `{value_1}`：示例占位符，不是固定字段名。

### C.5数据生成要求
- `new_schedule_name` 与 `schedule_name`、`new_media_name` 与 `media_name` 在同条数据中必须不同。
- 同一批数据中，作息方案名/媒体名/任务名不应高度重复，避免模型只记住少数名称。
